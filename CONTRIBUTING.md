# Contributing to Mutantcat Working Group

Thank you for considering a contribution to a Mutantcat Working Group project. Every report, pull request, review, and translation helps improve the projects in this organization.

## How to contribute

- Report a bug or request a feature by opening an issue in the repository.
- Ask questions and discuss ideas with maintainers in GitHub Discussions when the repository enables them.
- Fix a typo, improve documentation, add examples, or send a focused pull request.

## Before you start

1. Read the repository README to understand what the project does and how to run it.
2. Search existing issues and pull requests to avoid duplicates.
3. Choose work that matches your experience and the repository's current scope.
4. For code changes, understand how the project builds and tests locally before editing.

## Opening an issue

A useful issue report includes:

- The repository name, branch, and version you used.
- Steps to reproduce the problem.
- What you expected to happen and what actually happened.
- Screenshots, logs, or a small reproduction when available.
- For feature requests, describe the use case and the value the feature provides.

## Opening a pull request

1. Fork the repository and create a branch with a short, descriptive name.
2. Keep each pull request focused on one problem or feature.
3. Add or update tests when the change affects behavior.
4. Run the existing build, test, and lint commands described in the README or package metadata.
5. Describe what changed, how it was tested, and any screenshots for UI changes.
6. Keep the pull request small so it can be reviewed quickly.

Suggested branch names:

- `fix/descriptive-name` for bug fixes
- `feat/descriptive-name` for new features
- `docs/descriptive-name` for documentation changes
- `ci/descriptive-name` for build or release pipeline changes

## Commit style

Use plain, descriptive commit messages:

- `fix: handle empty input when exporting`
- `feat: add dark theme toggle`
- `docs: explain offline usage`
- `ci: add release asset checksums`

Do not combine unrelated changes in one commit.

## Review expectations

Maintainers may ask for clarifications or request changes. Keep discussions respectful, reply to questions, and update the pull request when needed. Merged contributions are appreciated and often credited in release notes or README contributor sections.

## Code of conduct

All participants must follow the repository's Code of Conduct. Harassment, personal attacks, or other unacceptable behavior will not be tolerated.
